# Phase 3 proposal: Ideas capture/detail and legacy Library presentation

Status: approved by the user on 25 November 2026. Implementation and actual verification are recorded in [PHASE-3-REPORT.md](PHASE-3-REPORT.md). The proposal below records the approved scope, including fully deferred context attachments and storage-compatible reuse of the live legacy pages.

This is a bounded visual conversion slice that continues from the selected Stitch designs while preserving the Phase 1 protections and the Phase 2 light foundation, shell, navigation, DM Sans assets, Home behavior and both persistence paths. Existing route captures remain regression evidence. They do not replace the original design sources listed below.

Initial idea capture remains the text-only flow already implemented in `IdeasPage`, calling `createIdea({ text })` from `lib/storage.ts`. Recompose the live `IdeasPage`, `IdeaDetail` and `ContentPage` around the selected Stitch layouts. Reuse their existing handlers, legacy record types, navigation and compatible Button/Input/Textarea/WorkspaceList primitives. Useful behavior is preserved; existing page layouts are replaced where they conflict with the selected designs.

`components/ideas/idea-capture.tsx`, `idea-list.tsx` and `components/content/content-list.tsx` use the separate workspace repository/types. Do not wire those components into these legacy routes, adapt records to their types, or switch storage paths to obtain their presentation. Both stores and the existing workspace editors remain intact.

Note/link forms describe context attachments to an existing idea. They are not initial capture forms. All attachment controls, menus, dialogs/sheets, persistence and Studio context selection remain deferred to a separately approved functional phase. Do not render interactive but unpersisted attachment surfaces or imply that existing records support them. The attachment rows below record future design sources only and are excluded from Phase 3 implementation.
