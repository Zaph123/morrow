DATA AND SAVE ISSUES — PRIORITY OVER OPTIONAL POLISH
A. lib/storage.ts:146–183: getContentItems catches bad JSON as []; createContent
   then writes a new array. Reproduced with synthetic malformed content: old raw
   bytes are overwritten. The guarded Home capture does not protect this path.
   createContent also returns a record on the server without a storage write.
   Audit all writers, not only creation of ideas; preserve failed reads as errors.
B. Corrected after live inspection, 24 November 2026: the HEADER Save condition
   excluded the normal dirty state, but another Save button below the editor
   remained available. Saving was not wholly unreachable. The timer could still
   mark later edits saved, and save errors lacked a catch/recovery path. Phase 1
   fixes the header condition and error/retry behavior, removes the timer, and
   tests failed-save retries and later unsaved edits through actual handlers.
C. idea-detail.tsx:69 promises clearing related-content connections on delete;
   deleteIdea only removes the idea. Resolve the relationship contract explicitly.
D. lib/workspace/storage.ts: canUseLocalStorage accesses window.localStorage
   before the read/write try block; a throwing getter can escape the error result.
E. See PERSISTENCE-AND-MIGRATION.txt: field/platform/status/ID incompatibilities
   mean neither storage system can simply replace the other.
