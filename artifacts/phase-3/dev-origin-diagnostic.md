# Development indicator diagnosis

The red `N 1 Issue` pill in the supplied screenshot was Next.js's development indicator, not a Morrow action or button error. The existing development server log recorded a blocked `/_next/hmr` request from `127.0.0.1`: the server was bound to `localhost`, and Next rejected the alternate loopback origin under its `allowedDevOrigins` protection. The browser also reported the HMR WebSocket handshake failure.

I repeated the same isolated Edge check through `http://localhost:3000/ideas`. The HMR warning and page errors were absent, and the indicator showed only the normal `N` button. The evidence is in [the diagnostic JSON](dev-indicator-diagnostic.json) and [the screenshot](dev-indicator.png). No dev-server setting was changed and the existing server was left running.

The button issue had a separate responsive cause. Morrow switches from Dialog to Bottom Sheet below 768 CSS pixels. At short view heights the sheet previously opened at its 52% detent with the body clipped, so the capture actions sat below the visible sheet area. The buttons did not shrink: their computed `flex-shrink` was `0`, labels stayed `nowrap`, and the rows had no overlap. The correction opens the sheet expanded at heights up to 600 CSS pixels and preserves text selection/focus across that responsive mode change. At 577×429 the capture footer becomes visible after a short body scroll; its 44px buttons are 269px and 261px wide with 12px between. At 717×522, Cancel is 79.75px and Save idea 88.98px wide with 8px between. The centered discard actions measure 116.55px and 84.38px with a 12px gap.
